# SEO Content Engine — /novosti (dymova-english.ru)

Восемь гейтов на каждую статью, чтобы качество не зависело от настроения.
Рутину (ресёрч, фактчек, разметку, публикацию) ведёт агент; темы, вердикт
фактчека и публикацию решает владелец.

## Важное отличие от оригинального EdgeLab-юзкейса

Оригинальный `ai-native-seo` — отдельный статический движок (свой React/Node
сайт). У нас сайт живёт на **Tilda** (project 2053071), и `/novosti` —
существующая Tilda-страница, не отдельный блог-движок. Поэтому:

- Публикация идёт не через `git clone ai-native-seo`, а через тот же путь,
  что и остальной контент сайта — Tilda-редактор или T123 HTML-блок (см.
  `.agents/skills/testing-foxinburg` для конвенций HTML-блоков проекта).
- Schema.org уже готов частично в `prototype/seo_schema/` (`faq.html`,
  `course_*.html`, `breadcrumb_*.html`) — новые статьи получают `Article` +
  `FAQPage` по тому же паттерну, не с нуля.
- **IndexNow не проверен на этом стеке.** Протокол требует файл-ключ в корне
  домена (`dymova-english.ru/<key>.txt`); неясно, даёт ли Tilda загрузить
  файл в корень или это нужно решать через прокси/поддомен. Открытый вопрос
  владельцу до первого реального пинга — не выдумывай обходной путь.
- Ресёрч-канал Sonar/Perplexity уже доступен в аккаунте как скилл
  `perplexity-research` — отдельная подписка Perplexity не нужна.
- x-research (X/Grok Live Search, нужен X Premium) — **не подключен**, не
  критичен для ниши языковой школы. Пропускаем, если владелец не решит иначе.

## Восемь гейтов

1. **Бриф и тип** — тема, аудитория, цель; гайд (пошаговый, с конкретикой:
   расписание экзамена, шаги подготовки) или статья (живой язык, без
   технических команд). Запросы бери реальные: позиции 4–15 в Яндекс.Вебмастере
   и частотность в Wordstat — просить у владельца доступ/скрин, если своего
   доступа нет. Заголовок по формуле «<реальный запрос> <год>: <хук>».
   Смотри также открытые темы в `wiki/03-seo.md` → «Чего не хватает»
   (ОГЭ/ЕГЭ/репетитор/взрослый английский/немецкий/китайский landing-темы
   годятся и как темы статей).

2. **Источники с весами** — свой опыт/база знаний школы первым делом, потом
   `perplexity-research` за фактами и ссылками. Каждое утверждение — со
   ссылкой. Противоречит официальному источнику (ФИПИ, посольство для
   языковых экзаменов и т.п.) — факт неверный.

3. **Драфт** — статья: живой язык, обязателен description (лид + мета).
   1–2 внутренних кросс-ссылки на существующие боевые страницы (см. sitemap,
   `wiki/03-seo.md`). Призыв в школу — прозой в последней секции, без
   рекламного блока.

4. **Фактчек вторым ревьюером** — вытащи атомарные утверждения, проверь
   каждое против источника: SUPPORTED / REFUTED / STALE / NEEDS_HUMAN. Если
   доступна вторая модель другой семьи (Codex/GPT) — прогони через неё;
   если нет — явно помечай NEEDS_HUMAN и отдавай владельцу, не подписывайся
   под непроверенным сама.

5. **Рубрика с порогом** — точность, польза, ясность, структура/SEO, голос
   (без хайпа и инфобиза), свежесть. Порог: статья ≥ 82 из 100. Ниже —
   дорабатывай, не публикуй.

6. **Линт-гейт** — стоп при: нет description, битая внутренняя ссылка, нет
   обязательной кросс-ссылки. Fail = не публикуем.

7. **Публикация + schema.org** — оформи как Tilda HTML-блок по конвенции
   проекта, добавь `Article`/`FAQPage` JSON-LD по образцу
   `prototype/seo_schema/faq.html`. IndexNow-пинг — только после того как
   владелец подтвердит рабочий способ класть ключ в корень домена (см. выше).

8. **Свежесть по TTL** — проставь дату проверки; статья ~90 дней до
   повторного фактчека (экзаменационные даты/форматы могут измениться раньше
   — ставь TTL короче для материалов про ОГЭ/ЕГЭ, ~30–60 дней).

## Красная зона (не делай без явного «да» владельца)
- Публикация на живой сайт (Tilda publish).
- Любые новые платные подписки/API (см. `CLAUDE.md`).
- Первый реальный IndexNow-пинг, пока способ размещения ключа не подтверждён.
