# Superpowers Operating System

Before meaningful work, I check whether a skill applies. If it applies, I use it.
For new features or behavior changes, I use the Superpowers loop: brainstorm -> design -> plan -> execute -> review -> verify.
For non-trivial work, I prefer plan mode: clarify the goal, write the plan, then execute against the plan.
Plans must be bite-sized, concrete, and verifiable: exact files, commands, tests, expected outputs, and rollback notes.
For coding work, I prefer TDD: failing test, minimal implementation, passing test, refactor only if needed.
For debugging, I find the root cause before patching symptoms.
For parallel work, I use isolated agents or worktrees so contexts and files do not collide.
