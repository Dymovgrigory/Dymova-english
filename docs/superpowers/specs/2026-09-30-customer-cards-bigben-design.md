# Карточки клиентов: номера из MAX/TG и сопоставление с BigBen

Дата: 2026-09-30. Часть A из двух (часть B — редизайн админки, отдельный цикл).

## Проблема (данные прода, 30.09)
- Карточек клиентов 128, телефон заполнен у 8, ФИО родителя у 34, имя ребёнка у 9.
- В диалогах бота номер есть у 44 человек, но в карточку он не попадает:
  `crm_store.upsert_customer_for_identity` получает phone только из событий
  мессенджера (там его нет), а не из `conv.lead`.
- Админка ищет ученика BigBen только по `customers.phone`, поэтому у 120 карточек
  всегда «Ученик с таким телефоном в BigBen не найден» — синхронизация BigBen
  при этом работает (1755 учеников, 1647 с телефоном), просто не используется.
- MAX: у Bot API есть кнопка `request_contact` (заметка в коде «нет такой
  кнопки» устарела). Telegram: `request_contact` уже есть, но показывается
  только под гейтом идентификации (на проде выключен).
- Номер из «открытого профиля» мессенджеры боту сами не отдают — только по
  нажатию «Поделиться номером».

## Решение
1. **Кнопка номера.** MAX: inline-кнопка `request_contact` на /start и рядом с
   приглашением на анкету, если номера ещё нет; вложение `contact` (vcf TEL)
   разбирается и сохраняется как подтверждённый номер. Telegram: reply-клавиатура
   `request_contact` на /start, если номера нет и анкета не заполнена.
2. **Любой номер → карточка.** Новый модуль `customer_sync`: после каждой
   реплики переносит из `conv.lead` в карточку ФИО родителя, имя ребёнка,
   возраст/дату рождения и телефон. Правило — только пустые поля, ручные
   правки менеджера не затираются (`_fill_empty_fields`).
3. **BigBen → карточка.** По телефону карточки находятся ученики BigBen
   (`bb_store.find_students_by_phone`). Пустые поля заполняются: имя ребёнка
   (ФИО ученика, при нескольких — через «, »), email. Связь хранится в
   `customers.metadata.bb_student_ids`, ставится тег «ученик школы».
   Выполняется при открытии Customer 360 и при переносе из диалога.
4. **Нет совпадения по телефону.** `bb_candidates` предлагает до 5 учеников по
   имени ребёнка/родителя (нечёткое сравнение `identify.name_matches`);
   менеджер привязывает одним кликом (`link_bigben`) — из BigBen тогда
   подтягиваются пустые поля и телефон. Надпись «не найден» заменяется
   причиной: «нет номера у клиента» / «номера нет в BigBen».
5. **Разовый перенос.** `customer_sync.backfill()` проходит все диалоги и
   карточки; запускается один раз на проде.

## Вне объёма
- Редизайн админки (часть B).
- Запись данных в BigBen из бота (только чтение).
- Автопривязка по имени без участия менеджера (риск чужой карточки).

## Ошибки и безопасность
- Любой сбой синхронизации логируется и не влияет на ответ клиенту.
- Номер нормализуется по последним 10 цифрам, как везде.
- Данные BigBen только дополняют пустые поля; при расхождении приоритет у
  ввода менеджера.

## Тесты
- `customer_sync`: перенос lead → карточка, не затирает заполненное,
  склейка по телефону, обогащение из BigBen, кандидаты, привязка, backfill.
- MAX: разбор contact-вложения (vcf и max_info), кнопка в стартовом меню.
- Admin API: crm360 находит ученика после переноса номера, отдаёт причину и
  кандидатов; эндпоинт привязки.
