# Тест на уровень английского — дизайн

**Дата:** 2026-07-26
**Статус:** утверждён владельцем, готов к планированию реализации.

## Контекст

Часть более крупной инициативы «сделать сайт живым и с большим количеством качественного контента», начатой после того как владелец увидел живые Skillbox/SkyEng и попросил перенять их функциональность (не визуальный стиль — текущий дизайн `dymova-english.ru` остаётся неизменным). Инициатива разбита на 4 независимых под-проекта:

1. **Тест на уровень английского** — этот документ.
2. Интерактивные виджеты на существующих страницах (плавающий чат с быстрыми ответами, баннер-таймер, фильтр-чипы) — не специфицировано.
3. Программные SEO-страницы под связки курс×возраст×район — не специфицировано.
4. Больше статей `/novosti` — не специфицировано, продолжение уже отлаженного пайплайна.

Каждый под-проект получает свой цикл спека → план → реализация. Этот документ — только про (1).

## Цель

Интерактивный инструмент-страница, где посетитель проходит короткий тест и получает оценку уровня английского (A1–C1), с мягким предложением записаться на разбор результата с методистом. Решает две задачи: реальная польза посетителю (самостоятельная оценка уровня — прямой аналог функции «Тест на уровень» у SkyEng, которой на нашем сайте нет вообще) и новый канал лидогенерации.

## Из чего явно исключено на этом этапе

- Немецкий и китайский языки — тест только по английскому. Остальные языки — отдельный шаг после того, как этот подход подтвердит себя.
- Адаптивное тестирование (подбор следующего вопроса по текущим ответам) — требует психометрической валидации, которой нет. Вместо этого — линейная система баллов.
- Изменение визуального стиля/бренда сайта — вне рамок этого под-проекта и всей инициативы.

## Структура теста

- 24 вопроса: по 4 вопроса на каждый из 6 уровней CEFR (A1, A2, B1, B2, C1, C2).
- Формат вопросов: множественный выбор (grammar + vocabulary). Без аудирования и чтения текста на этом этапе — упрощает и подготовку контента, и вёрстку.
- UI: один вопрос на экран, прогресс-бар сверху, кнопки «Далее»/«Назад». Не длинная форма со всеми вопросами сразу.
- Подсчёт: линейный по количеству правильных ответов на каждом уровне → результат вида «примерно B1» с коротким пояснением, что это значит на практике (не просто буква).

## Источник вопросов (важно — не выдумывать)

Вопросы берутся из открытых CEFR-банков вопросов (примеры уровня публикуются Cambridge English, British Council и аналогичными источниками для самопроверки). Собираются в структурированный JSON/YAML файл в репозитории (по аналогии с `bot/app/knowledge/data.yaml`).

**Жёсткое условие:** банк вопросов не публикуется на живой сайт, пока Коваленко Елизавета (методист школы) не просмотрит и не подтвердит корректность формулировок и уровневой привязки. Это ответственность за реальный (пусть и неформальный) образовательный контент, показываемый реальным пользователям под именем школы — здесь нельзя полагаться на то, что не-педагог (ни я, ни Григорий) верно оценил сложность/корректность вопроса.

## Результат и лид

1. После последнего вопроса — сразу показывается результат (уровень + короткое пояснение). Без принудительной формы перед просмотром результата — блокировать результат формой считается плохой практикой лидогенерации (высокий отказ, ощущение «обманули»).
2. Ниже результата — мягкий CTA: «Записаться на разбор результата с методистом».
3. При клике — компактная форма (имя + телефон), переиспользующая существующий паттерн `zayavka_modal()`/`ZAYAVKA_JS` из `prototype/build_course_pages.py`.
4. Отправка — на уже существующий `POST /api/lead` (тот же эндпоинт, что и обычная форма записи), с `source = "Тест на уровень"` и результатом теста (уровень) в `comment`. Никаких изменений на бэкенде не требуется — это чисто фронтенд-страница поверх уже готового API.

## Техническая реализация

- Новая страница `/test-na-uroven`, генерируется тем же пайплайном, что и остальные страницы (`build_static_site.py` + новый генератор фрагмента по аналогии с `build_subpages.py`/`build_course_pages.py` — plain HTML/CSS/JS, без фреймворка и без сборки, в соответствии с текущей архитектурой сайта).
- Банк вопросов — отдельный файл данных (JSON/YAML), не захардкожен в HTML-генераторе — чтобы Коваленко Елизавета (или будущие правки) могли редактировать вопросы, не трогая код вёрстки.
- Скоринг — чистый клиентский JS, без обращения к серверу до момента финальной отправки лида.
- Стиль — использует существующие CSS-переменные и паттерны сайта (`--purple-2`, `--orange`, `fxb-*` классы, Montserrat) — визуально неотличимо от остального сайта, никакого нового «дизайн-языка».

## Как проверяем перед публикацией

- Пройти тест целиком с разными комбинациями ответов, подтвердить, что результат вычисляется верно на всех границах уровней.
- Проверить реальную отправку лида (как делалось для формы записи ранее этим летом) — заявка доходит до BigBen с правильным `source`/`comment`.
- Дождаться подтверждения Коваленко Елизаветы по содержанию банка вопросов до публикации на прод.
