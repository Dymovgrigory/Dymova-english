## Подпроект 0. Анкета-форма вместо опроса в переписке

### Проблема
Регистрация идёт в чате 4 вопросами по одному (`app/registration.py`) — долго, клиенты
отваливаются. Согласия на обработку ПД не собираются вовсе.

### Поведение
1. Незарегистрированный пользователь пишет что угодно / `/start` → одно сообщение
   «Привет! Я Фокси 🦊 Заполните короткую анкету — 30 секунд, и всё откроется» и кнопка
   «📝 Заполнить анкету» (Telegram: `web_app`-кнопка на `/tg/#register`; MAX: link-кнопка
   на мини-приложение). На каждое следующее сообщение до регистрации — то же приглашение
   с кнопкой, без вопросов.
2. Мини-приложение без регистрации открывается сразу на форме; остальные вкладки
   недоступны до отправки.
3. Поля (один экран): ФИО родителя (prefill из профиля мессенджера), имя ребёнка,
   дата рождения или возраст ребёнка, телефон (в Telegram — кнопка «Поделиться номером»
   через `requestContact`, номер помечается подтверждённым).
4. Согласия:
   - `pd_child` — «Я родитель/законный представитель ребёнка и даю согласие на обработку
     его персональных данных» — обязательно, ссылка на полный текст;
   - `privacy` — «Принимаю политику конфиденциальности» — обязательно, ссылка;
   - `marketing` — «Хочу получать новости и акции школы» — **отмечена по умолчанию**,
     снять можно. Сохраняем факт «показана отмеченной, не снята».
   Тексты и ссылки — те же, что в Мире (`world/src/lib/legal.ts`, страницы
   `https://new.dymova-english.ru/legal/pd-consent`, `/legal/privacy`), версия `LEGAL_VERSION`.
5. «Готово» → сервер валидирует → лид в BigBen (как сейчас) + согласия → бот пишет
   в чат мессенджера «Спасибо! Всё открыто 🦊» → в мини-приложении открываются все вкладки.

### Технически
- `POST /api/miniapp/register` — только с подписанным initData (`identity.verified`).
  Серверная валидация полей (переиспользуем `_looks_like_name`, `extract_phone`,
  `_plausible_birthday/_plausible_age` из `registration.py`). Обязательные согласия
  не отмечены → 400.
- Хранение: поля — в `Conversation` (как сейчас), согласия — новая таблица
  `consents` в `crm_store` (platform, user_id, type, accepted, legal_version,
  channel, default_checked, created_at). Идемпотентно.
- BigBen: данные в поля лида, согласия с датой — в комментарий лида (`_build_note`).
- Админка бота: в карточке клиента блок «Согласия» (тип, дата, версия).
- Старый пошаговый опрос остаётся только для веб-виджета сайта.
- Уже зарегистрированные: анкету не повторяем; при отсутствии согласий в мини-приложении
  один раз показываем компактное окно только с чекбоксами.
- `_miniapp_access_state.message` для незарегистрированных → «Заполните анкету».

### Тесты
Валидация полей, обязательные согласия, marketing по умолчанию, идемпотентность,
отказ без подписи initData, приглашение с кнопкой вместо вопросов в TG и MAX,
запись в BigBen-заметку, миграция старых пользователей.

## Подпроект 1. Живые данные мини-приложения

### Педагоги и сотрудники
- Источник истины — блок команды на сайте (`prototype/block_team.html`, сейчас 17 человек;
  в мини-приложении 10, фото устарели).
- Модуль `app/knowledge/team_sync.py`: раз в час (`TEAM_SYNC_INTERVAL_MIN=60`) скачивает
  блок команды (URL настраивается, `TEAM_SYNC_URL`), парсит `article.fxb-card`:
  имя, роль, описание, фото, видео. Результат — в памяти + снимок на диск
  (`data/team_snapshot.json`), чтобы переживать рестарт.
- Ошибка сети/парсинга или пустой результат → остаётся последний удачный снимок;
  при отсутствии снимка — `data.yaml` как фолбэк.
- Обогащение из BigBen: педагог ↔ группы через `bb_group_meta.teacher`
  (сопоставление по фамилии), в карточке «ведёт: …».
- `/api/miniapp/info.team` отдаёт синхронизированный список.

### Расписание и места
- Уже синхронизируются из BigBen каждые 15 мин (`app/platform/sync.py`). Проверить на
  проде, что цикл жив.
- В ответ API расписания и в мини-приложение — «Обновлено N мин назад».
- Данные старше 60 мин → внеплановая инкрементальная синхронизация + предупреждение
  в watchdog.

### Тесты
Парсер блока команды на фикстуре, фолбэк на снимок/yaml, сопоставление педагог↔группа,
индикатор свежести, триггер внеплановой синхронизации.

## Подпроект 2. Помощник по ДЗ 2.0

### Принципы (зафиксированы владельцем)
- Готовый ответ не даём никогда. Учим решать. Педагогу не передаём.
- Объяснение «как решать» — подробное, по каждому пункту задания.

### Режимы
1. «Объясни, как решать» — вход: фото, текст, голосовое, аудиофайл.
   Структура: 📘 тема и правило → 🔎 разбор каждого пункта (какое правило, на что
   смотреть, первый шаг — без ответа) → ✏️ один похожий придуманный пример с решением
   по шагам → ✅ план → ❓ «пришли, что получилось».
2. «Проверь моё решение» — фото выполненного задания. По каждому пункту: верно / есть
   ошибка + наводящая подсказка без правильного варианта.
   Запуск: кнопка в мини-приложении, фраза «проверь» с фото в чате, либо фото,
   присланное после разбора (контекст диалога).

### Качество
- Разбор — роль `ROLE_VISION`/`ROLE_REASONING` (сильная модель).
- Проверяющий (`ROLE_CRITIC`) перед отправкой: нет ли готовых ответов, фактических ошибок,
  пропущенных пунктов. При замечаниях — одна перегенерация с замечаниями.
- Нечитаемое фото → просим переснять конкретную часть или надиктовать голосом.
  Отказа «не могу помочь» нет.

### Аудио
- Telegram: `voice`, `audio`; MAX: аудио-вложения; мини-приложение: запись с микрофона
  (MediaRecorder) и загрузка файла. Лимит 20 МБ / 5 мин.
- Модуль `app/speech.py`. Проверено на проде 2026-09-24: Cloudflare-воркер основного
  LLM-провайдера на `/audio/transcriptions` отвечает 403; `api.proxyapi.ru` (запасной
  провайдер из `LLM_FALLBACKS`, тот же ключ) — 200.
  Каскад: `gpt-4o-mini-transcribe` → `gpt-4o-transcribe` через провайдер из
  `STT_BASE_URL`/`STT_API_KEY` (пусто = первый провайдер из `LLM_FALLBACKS`, чей
  base_url содержит `proxyapi`) → опционально Yandex SpeechKit
  (`STT_YANDEX_API_KEY`, `STT_YANDEX_FOLDER_ID`).
  Обязателен параметр `prompt` с контекстом («школьник диктует задание, английские слова —
  латиницей…»): без него «вставь is или are» распознаётся как «из Ильяр», с ним — точно.
- Бот показывает «Услышал: …» и разбирает задание.

### Чат с Фокси в мини-приложении
- Отдельный экран ДЗ убираем; в чате кнопки «📸 Разобрать задание»,
  «✅ Проверить решение», «🎤 Голосом».
- При открытии чат подгружает историю переписки (последние 50 сообщений из CRM),
  фото показываются миниатюрами.

### Хранение и админка
- Таблица `homework_requests` (id, platform, user_id, conversation_id, channel, mode,
  input_type, image_path, audio_transcript, task_text, reply, critic_notes, created_at).
  Изображения — на диск `data/homework/`.
- Каждое обращение также пишется в общую переписку CRM (вход + ответ).
- Админка: раздел «Домашние задания» — список (дата, клиент, канал, режим), карточка
  с фото/текстом/распознанным голосом и ответом; фильтр по датам и режиму.

### Тесты
Выбор режима, STT-фолбэк, проверяющий и перегенерация, запись в `homework_requests`
и CRM, API админки, история чата; контрольный прогон на наборе типовых заданий
(английский, математика, русский) вручную с отчётом.
