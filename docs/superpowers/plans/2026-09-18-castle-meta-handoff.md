## Метод работы

Свежий агент на задачу, после каждой — отдельный ревьюер (соответствие требованиям
плюс качество), находки закрывает тот же исполнитель, затем точечная перепроверка
только по находкам. Задачи плана зависимы, параллелить исполнителей нельзя;
параллельно допустимо гонять ревью одной задачи и исполнителя следующей, если они
трогают разные файлы.

Бриф задачи извлекается скриптом:

```bash
bash ~/.claude/plugins/cache/superpowers-dev/superpowers/6.2.0/skills/subagent-driven-development/scripts/task-brief \
  docs/superpowers/plans/<план>.md N
```

## Окружение

- **Тесты бэкенда только через venv:** `cd world-backend && .venv/bin/python -m pytest -q`.
  Системный `python3` — 3.9, FastAPI не тянет и даёт ложные «ошибки окружения».
- Фронтенд: `cd world && npm test`, `npx tsc --noEmit -p .`, `npx eslint`, `npm run build`,
  `npm run dev` поднимает 127.0.0.1:3002.
- Сутки и недели считаются по Москве — `app/learning/clock.py` (`MSK`, `local_day`,
  `day_start_sql`). Часовой пояс строкой в SQL не хардкодить.
- Монеты выдаются только через `core.award`, списываются только через `core.spend`,
  всегда с ключом идемпотентности.

## Грабли, на которые уже наступили (не повторять)

1. **Ветка «Тренер» считает тренировки, а не выплаты.** Монеты за тренировку платятся
   не более двух раз в день, а при нулевой сумме строка в `coin_transactions` не
   создаётся. Счётчик берёт завершённые сессии из `learn_sessions`.
2. **Звание не отбирается при падении значения.** Оборвалась серия дней — уровень
   остаётся, а следующая цель считается от взятого уровня, иначе рядом со званием
   3 уровня показывалось «0 из 3».
3. **Порядок в `sessions.finish`:** сначала пометить сессию завершённой, затем
   `titles.sync`, затем собрать результат, затем записать его. Иначе звание за только
   что законченную тренировку опаздывает на одну тренировку. Ранний выход из `finish`
   обязан проверять, что результат не пустой, иначе клиент получит `null`.
4. **Деплой:** при выкладке пересобирается и `world-api`, поэтому нужен настоящий
   `WORLD_PLAYER_SECRET`; заглушка годится, только когда пересобирается один `world-web`.
   И обязательно `NEXT_PUBLIC_WORLD_API=https://new.dymova-english.ru`, иначе сборка
   уходит на домен без DNS и данные не грузятся.
