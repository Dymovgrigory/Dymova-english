## 1. ВИДЕНИЕ ПРОДУКТА

Развернуть на сайте `dymova-english.ru` **Личный кабинет (ЛК)** — единую веб-платформу, объединяющую три продукта:

1. **Дашборд** — операционный центр: расписание, посещаемость, прогресс, уведомления, статистика.
2. **Обучающая платформа** — тренажёр слов с картинками и озвучкой, домашние задания, словарные наборы по учебникам и уровням.
3. **Мир Фоксинбурга** — встроенная игровая вселенная (замок, башни Spotlight SP1–SP4), отдельный раздел внутри ЛК.

Роли: **родители учеников, педагоги, администраторы, владелец школы**.

Ключевое: **100% двусторонняя синхронизация** с CRM BigBen и мобильным приложением «Твоя школа» (у приложения есть API — см. раздел 3). Весь функционал приложения «Твоя школа», **кроме оплат**, должен присутствовать в ЛК.

**Оплат в ЛК НЕТ вообще** — ни приёма, ни отображения (решение владельца).

## 2. РОЛИ И ДОСТУП (решения владельца зафиксированы)

### 2.1. Родитель ученика
- Регистрация по номеру телефона (обязательное поле — ключ синхронизации с CRM). Подтверждение — **через ботов MAX или Telegram на выбор клиента** (бесплатно, механика из Мира: `requestContact` / подтверждение через бота, сессия 131). SMS не нужен.
- Несколько детей на одном номере → **переключатель профилей** в шапке ЛК; под каждого ребёнка — свой профиль (расписание, прогресс, Мир, тренажёр). Телефон ребёнка при отсутствии телефона родителя считается телефоном родителя.
- Видит: расписание, посещаемость, прогресс/успеваемость, домашние задания, игровой прогресс в Мире, тренажёр слов, уведомления, рейтинги и достижения.
- **НЕ видит:** ручные записи, важные комментарии и историю взаимодействия из CRM (внутренние пометки администрации — только для педагогов/админов/владельца).
- В Мире Фоксинбурга родитель — **наблюдатель**: ЛК-аккаунт родителя, профили — детей, свой игровой персонаж у родителя не нужен.

### 2.2. Педагог
- Функционал — **как в приложении «Твоя школа» сейчас** + контроль над доп. функционалом своих учеников (назначение наборов слов, ДЗ, просмотр прогресса по тренажёру и башням).
- **Педагоги НЕ видят номера телефонов клиентов** (жёсткое требование).

### 2.3. Администратор
- Всё, что педагог, плюс управленческие функции: группы, состав, расписание, пользователи, рассылки, заявки, модерация контента тренажёра.

### 2.4. Методист
- Права: **всё, кроме важных управленческих моментов** — создаёт и редактирует словарные наборы, назначает группам; не управляет пользователями, финансами и структурой.

### 2.5. Владелец школы
- **Функционал «Пульта Владельца» + приложения «Твоя школа»**, а также информация и статистика по новым ресурсам: **все цифры, рейтинги с конкретными данными участников** (кто, сколько, какие достижения — по тренажёру, Миру, группам, филиалам).

## 3. СИНХРОНИЗАЦИЯ (КРИТИЧНО)

### 3.1. Источники данных
- **BigBen CRM** (`panel.bigbencrm.ru`): ученики, группы, расписание, посещаемость. BigBen Public API v1 (read+write) + существующий платформенный слой репозитория (см. DEVLOG, «Платформенный слой BigBen API v1»).
- **Приложение «Твоя школа» и BigBen — одна система** (приложение полностью синхронизировано с CRM, решение владельца): данные приложения доступны через BigBen Public API v1 + вебхуки; отдельного API приложения не требуется.

### 3.2. Принципы
- **Расписание — мастер-источник BigBen**: расписание тянется из CRM в ЛК и приложение. Изменения в CRM → отражаются у всех.
- Частота обновления: достаточно **ручного обновления или автоматического с невысокой частотой** (polling раз в 5–15 мин + кнопка «Обновить») — реального времени не требуется.
- Номер телефона — сквозной идентификатор родительского аккаунта.
- Идемпотентность, журнал синхронизации для администраторов, аудит-лог изменений.
- Переносим из CRM **все данные**, но с разграничением видимости: ручные записи/история взаимодействия — не для родителей.
- Конфликты: правило «последняя валидная запись» + аудит-лог; для посещаемости — явные статусы.

## 4. ФУНКЦИОНАЛЬНЫЕ БЛОКИ

### 4.1. Дашборд
- Виджеты по ролям: ближайшие занятия, посещаемость, прогресс лексики, активность в Мире, ДЗ на проверку, рейтинги.
- Фильтры: ребёнок/группа/филиал/период.

### 4.2. Расписание и посещаемость
- Календарь (месяц/неделя/день), карточка занятия: группа, педагог, филиал/онлайн, тема, ДЗ, отметки.
- Педагог отмечает посещаемость в 1–2 касания.
- Уведомления об изменениях расписания (WebPush + дублирование в MAX/TG по привязке).

### 4.3. Домашние задания
- Педагог выставляет ДЗ (в т.ч. набор слов из тренажёра).
- Родитель/ученик: список, статусы «назначено / выполнено / проверено / просрочено», отметка о выполнении.

### 4.4. Коммуникации
- **Чат внутри ЛК — не в приоритете** (на старте достаточно уведомлений и существующих каналов: бот MAX/TG).
- Уведомления: **WebPush + MAX + Telegram** (по привязке аккаунта).

### 4.5. Оплаты
- **В ЛК отсутствуют полностью** (решение владельца).

## 5. ТРЕНАЖЁР СЛОВ (ЯДРО ПЛАТФОРМЫ)

### 5.1. Словарный контент на старте
- Наборы по учебникам: **My Level, Get Involved, Super Minds**, Spotlight 1–4.
- **Общеуровневые словари от Pre-A1 и далее** по уровням.
- **Словарь работает по порядку** (последовательное изучение, как в приложении).
- Любые тематические наборы — конструктором (педагог/методист/администратор).

### 5.2. Конструктор наборов
- Карточка слова: слово, транскрипция, перевод, картинка, озвучка, пример, часть речи.
- Картинки: **реалистичные и понятные** — подбираются из открытых онлайн-источников/словарей; обязательно ясно, что за слово изображено.
- Озвучка: **автоматическая TTS** на старте (британский/американский), с возможностью позже заменить своей записью.
- Импорт пакетами (CSV/Excel + медиа), банк слов школы, привязка к учебникам и уровням.

### 5.3. Типы тренировок (все, **кроме произношения/распознавания речи** — исключено владельцем)
- «Слово → перевод», «Перевод → слово», аудирование, написание (spell), «Найди пары», контекстные предложения, смешанный экзамен.
- Интервальные повторения (SRS), статусы слова «знаю / сомневаюсь / не знаю» — видимы педагогу.
- Словари изучаются **в тренажёре в отдельном разделе** (не пропускной для башен Spotlight — башни и тренажёр независимы, решение владельца).

### 5.4. Назначение и права
- Назначение набора: группе / нескольким группам / башне-классу / возрасту / индивидуально (таргетинг из исходного запроса).
- Методист — полный контент, без управленческих функций; педагог — своим группам; телефоны клиентов педагогам не показываются.

### 5.5. Статистика
- По ученику/группе/педагогу: охват, точность, темп, проблемные слова; экспорт PDF/Excel; рейтинги с конкретными данными участников (для владельца).

## 6. МИР ФОКСИНБУРГА В ЛК

- Отдельный **раздел внутри ЛК** (не отдельная вкладка/фрейм на стороне).
- Единый вход без повторной авторизации (SSO по токену ЛК); прогресс общий между ЛК, приложением «Твоя школа» и самим Миром.
- Арт и стиль — «Живая миниатюра» (`docs/world/STYLE_LOCK.md`, промпты `world-pipeline/prompts/ART_DIRECTION.md`) — **не менять**.
- Родитель видит прогресс ребёнка (этажи, звёзды, лига, трофеи) в дашборде ЛК.

## 7. РЕГИСТРАЦИЯ И ПРОФИЛИ

1. Регистрация: **телефон обязателен** (+ имя). Подтверждение — **через ботов MAX или Telegram на выбор клиента**. Соц. входы — не нужны.
2. Сопоставление: нормализация номера → поиск в BigBen → привязка карточек учеников.
3. Телефон ребёнка = телефон родителя, если в CRM не указан телефон родителя.
4. Несколько детей → переключатель профилей, под каждого ребёнка отдельный профиль.
5. Номера нет в CRM → **гостевой режим**: доступны **Мир, словари для тренировки слов, рейтинги и достижения** + подсказка обратиться в школу для привязки.
6. Языки интерфейса: **русский + английский** (нужен EN — решение владельца).

## 8. ДИЗАЙН И КАЧЕСТВО

- Референсы **структуры и наполняемости** — Skyeng и Duolingo; **цвета, формы, кнопки, визуальный стиль — фирменные нашей школы** (фиолетовый, Фокси).

- Адаптивность: **ПК и телефон** (360 px+), mobile-first для родительских сценариев.

## 9. РАЗМЕЩЕНИЕ И SEO (решение + рекомендация)

- **Решение владельца:** новый ЛК разворачивается на поддомене **`lms.dymova-english.ru`** (там сейчас старый LMS). Кнопки «Вход в ЛК» на сайте уже ведут на `lms.` — при развёртывании нового ЛК на этом поддомене менять ссылки не придётся, старый LMS будет заменён.
- Маркетинговый сайт остаётся статическим на основном домене (всё SEO-продвижение — страницами `dymova-english.ru`); закрытая зона ЛК отдаётся с `noindex` и на поиск не влияет.
- Вариант «внутри текущего статического сайта» технически не подходит для приложения с личными данными и синхронизацией — поэтому отдельное приложение + единая точка входа с сайта.

## 10. ТЕХНИЧЕСКИЙ СТЕК (предложение)

- Фронт: Next.js + TypeScript (переиспользовать `world/` — компоненты, деплой-инфраструктуру `new.dymova-english.ru`).
- Бэкенд: `world-backend` (FastAPI) → расширение до платформенного API ЛК; BigBen Public API v1; адаптер к API «Твоя школа» (доступ запросить у владельца).
- БД: PostgreSQL/SQLite (как в world-backend) для пользователей, наборов слов, прогресса; CRM — мастер учеников/групп/расписания.
- Медиа: файловое хранилище + TTS; картинки — реалистичные из открытых источников с ручным контролем качества.
- Арт деталей/рамочек/мелких элементов: Meshy (ключ `msy_…` — тот же аккаунт, что и у world-pipeline; оба ключа валидны, баланс 2 990 кредитов).

## 10А. ОТКРЫТИЯ ЭТАПА 0 — ДОКУМЕНТАЦИЯ BIGBEN (2026-11-02)

Изучена официальная документация (`developers.bigbencrm.ru`, спецификация OpenAPI v1) и существующий код (`bot/app/platform/`):

**Публичный API v1 закрывает (read):** справочники (филиалы, предметы, программы, уровни), группы (+ расписание группы, вместимость, свободные места), занятия окном дат (id, дата, время, группа, филиал), ученики (id, ФИО, телефон, email, баланс, активные группы), оплаты. **Write:** лиды, запись на пробный, зачисление в группу.

**НЕ закрыто публичным API:** посещаемость (read), домашние задания, темы занятий, данные педагогов.

**Решения по незакрытым областям:**
- **Посещаемость** — через BigBen-вебхуки: событие `lesson.completed` приходит с `visit_status` (1 = был) в момент отметки педагогом в CRM/приложении (инфраструктура уже есть: `bot/app/platform/webhooks.py`, HMAC-подпись, дедупликация). История посещаемости в ЛК = журнал webhook-событий.
- **Домашние задания** — храним в собственной БД ЛК (BigBen их не ведёт), привязка к занятию по `lesson_id`.
- **Педагоги** — нет в публичном API; вариант: внутренний токен пульта владельца (`lk.bigbencrm.ru`, паттерн `bot/scripts/import_group_meta.py`, токен живёт ~30 дней) либо ручное ведение состава в ЛК.

⚠️ Ключ сейчас, судя по проверке, работает на read; скоуп `write` (лиды/пробные/зачисление) подтвердить на Этапе 1 при первой записи.

   - **Разведка API (критично):** публичный API v1 НЕ отдаёт составы групп — `active_groups` пусты у всех учеников, фильтры `student_id`/`group_id` в `GET /lessons` игнорируются (возвращаются все занятия школы), вложенных эндпоинтов нет. Поэтому привязки ученик↔группа копятся из вебхука `group.enrolled` (таблица `lk_group_members`, статусы active|left) + планируется разовая полная синхронизация через внутренний токен пульта (`BIGBEN_INTERNAL_TOKEN`) после деплоя.
   - world-backend: `GET /api/lk/schedule` (Bearer; окно ≤62 дней; 401/409 `bad_dates`/`window_too_large`/`profile_not_found`; фильтр занятий по группам ученика = union `active_groups` профиля + `lk_group_members`; join с `lk_attendance`), внутренние relay `POST /api/lk/attendance` и `POST /api/lk/group-members` (HMAC `WORLD_BRIDGE_SECRET`, свежесть ±300 с). Клиент: `lessons()` с кэшем 10 мин (макс. 20 окон).
   - Формат занятия из CRM: `{id, date, starts_at/ends_at (ISO UTC), group{id,caption}, filial{id,caption}}` — педагогов и тем в публичном API нет (решение по педагогам — через внутренний токен, отложено).
