# FOXINBURG AI 2.0 — ROADMAP

План модернизации по итогам [AUDIT.md](AUDIT.md). Дата: 13.08.2026.

**Принцип:** не переписывать надёжную инфраструктуру (дедлайны, локи, дедупликация, 325 тестов),
а заменить AI-ядро и интерфейс. Каждая фаза — отдельный коммит, после каждой: тесты → smoke.

---

## 0. Выбор LLM (главное решение)

### Текущее состояние
`meta-llama/llama-3.3-70b-instruct:free` через OpenRouter. Каскад фолбэков пуст.
Оценка из аудита: русский — «переводной», structured output отсутствует, free tier даёт 429 и
задержки, из-за чего в конфиге стоит `SLOW_NOTICE_SEC=12` и `REPLY_TIMEOUT_SEC=60`.

### Сравнение кандидатов

Транспорт проекта — OpenAI-совместимый `chat/completions` (httpx). Через OpenRouter доступны
почти все модели без смены кода, поэтому сравниваем по существу, а не по протоколу.

| Модель | Русский диалог | Structured output | Latency | Цена $/1M in/out | Вывод |
|---|---|---|---|---|---|
| **Claude Sonnet 5** | отличный, живая интонация | JSON Schema, strict tools | средняя | 3 / 15 (интро 2/10 до 31.08) | 🥇 **основная reasoning-модель** |
| Claude Haiku 4.5 | хороший | JSON Schema | быстрая | 1 / 5 | 🥈 **fast-модель** (intent, критик, классификация) |
| Claude Opus 5 | лучший | JSON Schema | выше | 5 / 25 | избыточен для чата продаж; держим как опцию |
| DeepSeek V3 | приличный, местами калька | JSON mode | средняя | ~0.3 / 1.1 | 🥉 **fallback** — дёшево и работает |
| GPT-4o-mini | хороший | JSON Schema | быстрая | 0.15 / 0.6 | альтернативный fallback |
| Qwen 2.5 72B | средний | JSON mode | средняя | ~0.4 / 1.2 | не даёт преимуществ |
| Llama 3.3 70B free | слабый (текущий) | нет | плохая | 0 | 🔻 только последний фолбэк |
| YandexGPT 5 / GigaChat | нативный русский | ограниченный | средняя | ₽ | ⚠️ см. блок ПДн ниже |

### 🔴 Отдельно: персональные данные (152-ФЗ)

Бот собирает **ФИО ребёнка, дату рождения, телефон родителя** и отправляет историю диалога
в LLM. Это персональные данные несовершеннолетних. Передача их в зарубежное облако —
юридический риск, который нельзя решить кодом.

**Решение в архитектуре (реализуется в Phase 2):** слой **PII-редакции** перед отправкой в LLM.
Имена, телефоны и даты заменяются на плейсхолдеры (`{{PARENT_NAME}}`, `{{CHILD_NAME}}`,
`{{PHONE}}`), ответ модели восстанавливается обратно. Модель получает контекст «родитель
{{PARENT_NAME}}, ребёнку 9 лет», не получая реальных данных. Это снимает основной риск
независимо от выбора провайдера и оставляет дверь открытой для YandexGPT/GigaChat, если школа
решит переехать на российское облако — Gateway это поддержит без переписывания.

### Итоговый production stack

```
LLM Gateway
├── REASONING  → claude-sonnet-5     (диалог, SMART, рекомендации)
├── FAST       → claude-haiku-4-5    (intent, критик, классификация, эмоции)
├── VISION     → claude-sonnet-5     (разбор фото домашки)
├── CRITIC     → claude-haiku-4-5    (оценка ответа перед отправкой)
└── FALLBACK   → deepseek-v3 → llama-3.3-70b:free
```

Роли настраиваются переменными окружения (`LLM_ROLE_REASONING=...`), поэтому смена модели —
это правка `.env`, а не кода. Обратная совместимость: если роли не заданы, всё работает на
старых `LLM_MODEL`/`LLM_FALLBACKS`.

## Фазы

### Phase 1 — Аудит ✅
`AUDIT.md`, `FOXINBURG_AI_2_ROADMAP.md`. Базовый прогон: 325 тестов зелёные.

### Phase 2 — LLM Gateway
- `app/llm_gateway.py`: роли моделей, structured output (JSON Schema + устойчивый парсер),
  PII-редакция, метрики latency/ошибок по ролям.
- `app/llm.py` остаётся как транспорт (каскад, ретраи, бюджет) — Gateway надстраивается над ним.
- Тесты: роль→модель, деградация при отсутствии JSON-режима, редакция/восстановление PII.
- **Готово, когда:** `get_gateway().structured(...)` возвращает валидированный объект или None,
  никогда не бросает, укладывается в бюджет.

### Phase 3 — SMART
- `app/smart.py`: модель потребности `NeedProfile` (Situation / Motivation / Aim / Relevance).
- Гейт продаж: `sales_allowed` вычисляется из полноты профиля, а не из желания промпта продать.
- Правило одного вопроса: не более одного уточняющего вопроса на реплику.
- **Готово, когда:** на «сколько стоит?» без контекста бот задаёт один уточняющий вопрос,
  а не выдаёт прайс и не зовёт на диагностику.

### Phase 4 — Память
- Расширить `Conversation` до профиля: goals, motivations, pain_points, objections,
  decision_maker, urgency, lead_temperature, previous_experience, budget, schedule.
- Суммаризация длинных диалогов (сейчас всё старше 20 сообщений просто выбрасывается).
- Естественное возвращение: «Мы обсуждали занятия для Маши — продолжим?» вместо шаблона.
- Обратная совместимость чтения старых JSON-записей обязательна.

### Phase 5 — Conversation engine
- Мягкая state machine с разрешёнными откатами (`RECOMMENDATION → DISCOVERY`).
- Intent-слой: regex как быстрый путь, LLM structured output — когда regex не уверен.
- Эмоциональный слой: mood + interest + doubt вместо 25 подстрок.
- Разбор `ai_core._route()` на явные обработчики.

### Phase 6 — AI Critic
- Проверка ответа перед отправкой: релевантность, естественность, отсутствие давления,
  соответствие SMART, отсутствие выдуманных фактов, отсутствие запрещённых конструкций.
- При провале — одна регенерация с замечаниями критика, потом отдаём лучшее из двух.
- Жёсткий бюджет: критик не должен увеличивать время ответа больше чем на ~1.5 с.

### Phase 7 — Knowledge / RAG
- Улучшить поиск: синонимы, нормализация, взвешивание.
- Убрать три костыля вокруг «сколько стоит?» (`ai_core.py:485-509`) — они лечат симптом.
- Recommendation engine: `recommended_program + confidence + reason + next_best_action`.

### Phase 8 — Telegram
- Deeplink `/start <payload>` (сейчас теряется вместе с UTM).
- Фото в чате → vision-разбор домашки (уже работает в мини-аппе).
- `_reply_while_alive` на всех медленных путях.

### Phase 9 — MAX 🔴
- **Миграция на `platform-api2.max.ru`** + корневой сертификат Минцифры в Dockerfile.
- Ретраи, 429, keep-alive в `MaxClient` (сейчас нет ничего).
- Кнопка `open_app` для мини-приложения.

### Phase 10-11 — Mini Apps + WOW UI
- Убрать emoji-лис (favicon, greeting, 6 плиток).
- Подключить настоящего маскота: `prototype/mascot/foxi-splash.webp` мгновенно,
  `foxi-rigged.glb` (726 КБ, 6 анимаций) — лениво, только на достаточных устройствах.
- Дизайн-система FOXINBURG FUTURE EDUCATION: крупная типографика, асимметричная сетка,
  frosted glass, ambient light — дозированно.
- Микровзаимодействия, переходы экранов, скелетоны, haptics.
- `prefers-reduced-motion`, контраст, размеры тач-целей.
- Fallback для слабых устройств: без WebGL — статичный маскот, интерфейс не страдает.

### Phase 12 — Benchmark
100+ сценариев с expected behavior по категориям ТЗ (цена, «дорого», «ребёнок не хочет»,
страх говорить, сравнение с конкурентами, негатив, повторное обращение, длинный диалог).
Прогон offline против детерминированных проверок + опционально против живой LLM.

### Phase 13-15 — Perf / Security / QA
- Rate limit на `/api/lead`, TTL для `processed_events`, удаление мёртвого `dedup.py`.
- Prompt injection: проверка исходящего ответа на утечку системного промпта.
- keep-alive HTTP-клиенты, ограничение кэша диалогов.
- Playwright E2E мини-аппов, финальный прогон.

## Criteria of Done

- Бот не продаёт до понимания потребности (проверяется бенчмарком).
- Задаёт один вопрос за раз, помнит прошлые разговоры, признаёт незнание.
- MAX работает на актуальном API; Telegram — deeplink, фото, кнопки.
- Mini Apps: настоящий маскот, ноль emoji-лис, нет ошибок в консоли, работает на слабом телефоне.
- ПДн не уходят в LLM в открытом виде.
- Тесты зелёные, включая 325 существующих.

### Что нашлось по дороге

Дефекты, которых в аудите не было — их выявили собственные тесты и проверка
в браузере:

- Восстановление имён из хранилища ПДн давало «записываю **Маша**» —
  понадобился модуль склонения (`app/morph.py`).
- «Ребёнок не хочет заниматься английским» получало в ответ каталог
  программ — ровно то, что ТЗ приводит как пример недопустимого.
- «Я не хочу записываться, просто спрашиваю» запускало сбор заявки:
  разбор по ключевым словам не видел отрицания.
- Поиск по базе находил «У вас есть носитель языка?» на вопрос «Кто у вас
  педагоги?» — по слову «вас».
- Без модели бот показывал человеку выгрузку документов с заголовками FAQ,
  то есть задавал вопросы вместо ответа.
- Публичная форма заявки не имела ограничения частоты, а журнал событий рос
  без предела.
- Тесты ходили в интернет: живой веб-поиск не был выключен, один сценарий
  ждал двадцать секунд.
- Заголовок плитки в MAX-приложении наследовал приглушённый цвет и падал до
  контраста 3:1.

### Что осталось за рамками

- Кнопка запуска мини-приложения из клавиатуры бота MAX: в официальной
  документации Bot API такого типа кнопки нет, мини-приложение привязывается
  в кабинете MAX Бизнес и кнопка появляется сама. Гадать про формат нельзя —
  неверный тип роняет всю клавиатуру сообщения.
- Прогон бенчмарка против живой модели (`scripts/run_benchmark.py`) — платный
  и требует ключа провайдера, поэтому запускается вручную.
