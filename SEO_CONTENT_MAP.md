# Контент-карта и редакционный план — dymova-english.ru (Фоксинбург, Долгопрудный)

Версия: 1.0 · Дата: 20.08.2026 · Владелец: Content Strategist
Связанные документы: `SEO_semantic_core.md` (кластеры 0–11), `SEO.md`, `AUDIT_OBSHIY.md`.

> **Жёсткие правила проекта (не нарушать):**
> 1. Каждая страница уникальна и полезна. Никаких doorway-страниц («один текст + подмена города/класса»), никакого AI-спама.
> 2. Пропорция: **80% evergreen / 20% commercial**. Информационный контент — фундамент трафика; коммерческие страницы — только точки конверсии.
> 3. Объёмы из фаз ниже — это **потолок мощности при соблюдении Quality Gate**, а не обязательство спамить. Если качество не проходит gate — страница не публикуется, темп снижаем.
> 4. Генерация страниц — только через существующий пайплайн: шаблоны `landing` / `feed` / `article` в `prototype/build_subpages.py`, алиасы — в `build_static_site.py`. Новые разделы добавлять как новые шаблоны/конфиги, не хардкодить HTML вручную.

### 1.2. Слои и правила связывания

- **Pillar** — программная страница (существующие URL). Содержит: оффер, для кого, программа, преподаватели, цены, FAQ (schema FAQPage), CTA. Ссылается вниз на кластерные статьи и хабы.
- **Cluster-хаб** — раздел (`/blog/`, `/grammar/`, `/tests/`, `/dictionary/`, `/resources/`, `/faq/`). Каннибализации с Pillar нет: хабы собирают информационный интент (I), пиллары — коммерческий (C). Хаб всегда ссылается «вверх» на Pillar с коммерческим анкором.
- **Article** — одна статья = один интент = один целевой запрос. Минимум 2 внутренние ссылки: на Pillar и на соседнюю статью кластера.
- **FAQ** — либо блок на странице курса (FAQPage schema), либо отдельная страница `/faq/<tema>` при ≥8 вопросах.
- **Tool** — интерактив (раздел 4). Страница инструмента ссылается на Pillar и наоборот.
- **Conversion** — единый CTA-блок во всех шаблонах: «Бесплатный пробный урок + диагностика уровня».

## 2. Контент-план на 12 месяцев

### Фазы и принципы набора объёма

| Фаза | Месяцы | Накопительный объём | Фокус |
|---|---|---|---|
| Phase 1 | 1–3 | до 100 страниц | Хабы-скелеты, E-E-A-T-фундамент, топ-кластеры (0,1,2,3,6,7), первые инструменты |
| Phase 2 | 4–6 | до 300 страниц | Полная грамматика A1–B1, словарь по темам, ОГЭ/ЕГЭ-кластер, FAQ-раздел |
| Phase 3 | 7–9 | до 500 страниц | Грамматика B2–C1, длинный хвост блога, тесты, ресурсы для скачивания |
| Phase 4 | 10–12 | до 1000 страниц | Глубинные подтемы, UGC/отзывы-кейсы, сезонные (лето/сентябрь), обновление и консолидация |

**Распределение по типам (держим 80/20):** из каждых 100 новых страниц ~80 информационных (статьи, грамматика, словарь, тесты, ресурсы, FAQ), ~20 коммерческих/конверсионных (новые программные страницы, гео-подстраницы филиалов, лендинги сезонных акций). Дверwey-гео-страницы под соседние города **не делаем** — гео ограничиваем Долгопрудным и реальными филиалами.

**Темп:** Phase 1 ≈ 30–35 стр/мес, Phase 2–3 ≈ 65–70 стр/мес, Phase 4 ≈ 100–170 стр/мес за счёт словаря и тестов (короткие форматы с жёстким шаблоном качества).

## 3. Разделы-хабы

Общее: каждый хаб — шаблон `feed` (список) + первый экран с пояснением «для кого раздел». Все страницы хабов добавляются конфигом в `build_subpages.py` / алиасами в `build_static_site.py`.

### 3.1. `/blog/` — блог для родителей
- **Аудитория:** родители детей 3–16 (основной), взрослые ученики (вторичный).
- **URL:** `/blog/` (хаб) → `/blog/<slug>` (статья). Подкатегории логические (теги), без физических `/blog/doshkolniki/*` на старте — проще поддержка; теги: `doshkolniki`, `nachalnaya-shkola`, `podrostki`, `oge`, `ege`, `vzroslym`, `leto`.
- **Шаблон статьи (`article`):** H1 → лид (2–3 предложения с ответом) → содержание → 4–8 H2 → практический блок «Что сделать сегодня» → FAQ (3–5 вопросов, FAQPage schema) → блок автора (имя, роль, фото, ссылка на `/about/prepodavateli#<id>`) → CTA «пробный урок» → 3 похожие статьи. Schema: `Article` + `FAQPage` + `BreadcrumbList`.

### 3.2. `/grammar/` — грамматика A1–C1
- **URL:** `/grammar/` (хаб по уровням) → `/grammar/<uroven>/` (A1…C1) → `/grammar/<uroven>/<tema>` (например `/grammar/a2/past-simple`).
- **Шаблон:** правило простым языком → таблица/схема → 10 примеров с переводом → типичные ошибки русскоязычных → 10 упражнений с ответами (раскрывающиеся) → мини-тест (5 вопросов) → ссылки на соседние темы уровня → CTA курса `/grammar`.
- **Важно:** хаб не конфликтует с существующей страницей курса `/grammar` — курс переезжает на `/grammar-kurs` или остаётся с каноническим разделением: `/grammar` = хаб, страница курса получает slug `/kurs-grammatiki` с 301-редиректом. Решение фиксируем в техническом плане до запуска Phase 1 (см. риски).

### 3.3. `/tests/` — тесты уровня
- **URL:** `/tests/` (хаб) → `/tests/uroven-anglijskogo` (взрослый), `/tests/uroven-dlya-rebenka`, `/tests/gotovnost-k-oge`, `/tests/gotovnost-k-shkole`, далее тематические `/tests/<tema>`.
- **Шаблон:** интерактивная форма (JS, без сервера — подходит под статику) → результат с интерпретацией → рекомендация программы (ссылка на соответствующий Pillar) → CTA «точная диагностика на пробном уроке». Schema: `Quiz` (или `WebPage` + FAQ).

### 3.4. `/dictionary/` — слова по темам
- **URL:** `/dictionary/` → `/dictionary/<tema>` (family, animals, food, school…).
- **Шаблон:** 20–40 слов с транскрипцией и переводом → озвучка (Web Speech API, без аудиофайлов) → карточки для запоминания → мини-игра «найди пару» → упражнение → ссылка на тренажёр слов и на возрастной Pillar.

### 3.5. `/resources/` — материалы
- **URL:** `/resources/` → `/resources/<slug>` (чек-листы, рабочие листы, план подготовки к ОГЭ в PDF).
- **Шаблон:** описание материала → превью → скачивание (PDF, без формы email на старте; позже — обмен на подписку как эксперимент) → связанные статьи → CTA. Цель — ссылки и шеры, не лиды любой ценой.

### 3.6. `/faq/` — центр вопросов
- **URL:** `/faq/` (хаб) → `/faq/<tema>` (`/faq/oge`, `/faq/doshkolniki`…).
- **Шаблон:** 8–20 вопросов аккордеоном, каждый ответ 2–4 предложения + ссылка на статью/курс. Schema: `FAQPage`. Правило: FAQ-страница создаётся только когда накопилось ≥8 реальных вопросов (из чата бота, звонков, Wordstat).

## 4. Интерактивные инструменты: очередность и зачем

Приоритет по соотношению «затраты / ссылочная и конверсионная отдача». Всё — клиентский JS на статике, без бэкенда.

1. **Тест уровня английского (взрослый + подростки) — первым (месяц 1–2).** Почему: самый шерящийся и линкуемый формат в нише, прямой мост к P9/P3 и к конверсии «диагностика на пробном уроке». 25–30 вопросов адаптивной сложности, результат A1–C1 с интерпретацией.
2. **Тест уровня для ребёнка / «готов ли к школе» — вторым (месяц 2–3).** Почему: эмоциональный драйвер для родителей (основная аудитория), даёт заявки в кластеры 1, 2, 6.
3. **Калькулятор стоимости — третьим (месяц 3–4).** Почему: снимает главный барьер («сколько стоит»), снижает нагрузку на администратора, повышает конверсию `/tseny`. Вход: возраст, формат (онлайн/офлайн), частота → выход: вилка цены + CTA.
4. **Тренажёр слов — четвёртым (месяц 5–6).** Почему: retention-инструмент и повод для регулярных возвратов (brand-запросы, поведенческие факторы); основа для роста `/dictionary/`. Механика: карточки + интервальные повторения в localStorage.
5. Позже (Phase 3+): мини-тесты по грамматическим темам, генератор плана подготовки к ОГЭ/ЕГЭ.

Каждый инструмент получает: посадочную страницу с уникальным текстом (не голая форма), FAQ, ссылки с релевантных Pillar и статей, Schema.

## 5. Quality Gate — чек-лист публикации

Каждая страница перед публикацией проходит проверку по 10 критериям. Оценка 0/1 по каждому, **проходной балл — 9/10**, причём критерии 1–4 обязательны (0 по любому из них = запрет публикации независимо от суммы).

| # | Критерий | Проверка |
|---|---|---|
| 1 | **Uniqueness** | Текст уникален (≥90% по text.ru / Advego), не пересказ существующей страницы сайта, нет дубля интента с другим URL |
| 2 | **Accuracy** | Факты проверены (форматы ОГЭ/ЕГЭ — по ФИПИ текущего года; цены/расписание — по актуальным данным школы); нет выдуманных утверждений |
| 3 | **Intent-match** | Страница отвечает на целевой запрос в первых 100 словах; структура соответствует топу выдачи по запросу, но не копирует конкурентов |
| 4 | **Original value** | Есть то, чего нет у конкурентов: опыт школы, примеры из занятий, данные учеников (анонимно), авторские упражнения, локальный контекст Долгопрудного |
| 5 | **E-E-A-T** | Указан автор (реальный преподаватель), есть блок «об авторе», при необходимости — рецензент; дата публикации/обновления |
| 6 | **Internal links** | ≥1 ссылка на Pillar кластера, ≥1 на соседнюю статью, ≥1 входящая ссылка добавлена с существующих страниц |
| 7 | **Schema** | Разметка по типу (Article/FAQPage/Quiz/Course) + BreadcrumbList; валидация в Rich Results Test без ошибок |
| 8 | **UX** | Читаемость: абзацы ≤4 строк, подзаголовки каждые 300–400 слов, списки/таблицы где уместно; мобильная вёрстка проверена |
| 9 | **Perf** | Страница проходит бюджеты: LCP < 2.5с, CLS < 0.1, вес < 500 КБ без учёта шрифтов; изображения webp с width/height |
| 10 | **Conversion** | Есть релевантный CTA (не обязательно «купить» — для I-страниц допустим «тест» или «материал»); CTA ведёт на рабочую форму |

Журнал проверок — чек-лист в PR каждой страницы. Страница с баллом <9 дорабатывается, не публикуется.

## 6. Контент-refresh: правила обновления

### 6.1. Существующие 15 статей `/novosti-*`
Текущие статьи живут в `/novosti` (новостной формат). План:

1. **Аудит (месяц 1):** для каждой статьи фиксируем — целевой запрос, трафик (Метрика/Вебмастер), индексацию, дубликаты интента с новым планом.
2. **Три судьбы:**
   - **Keep & Refresh** — статья с интентом из нового плана: обновляем текст до Quality Gate, переносим в `/blog/<slug>` с 301-редиректом со старого URL, проставляем дату обновления.
   - **Merge** — 2+ статьи с одним интентом: склеиваем в одну сильную, остальные URL — 301 на неё.
   - **Leave** — чистые новости школы (события, праздники): остаются в `/novosti`, получают метку «новость», без претензии на evergreen-трафик.
3. **Ритм:** 5 статей/месяц, чтобы за Phase 1 обработать все 15.

### 6.2. Программные страницы (17 лендингов)
- **Ревизия раз в квартал:** цены, расписание, преподаватели, фото — всегда актуальные (критерий Accuracy).
- **Раз в 6 месяцев:** проверка intent-match по свежей выдаче; доработка блоков, которые спрашивает топ SERP, а у нас нет.
- **Сезонные:** `/letnyaya-akademiya` — обновление в марте (анонс смены) и мае (расписание/цены); `/podderzhivayushchie-online` — в апреле.
- **Даты:** на каждой evergreen-странице — «Обновлено: <дата>»; обновление даты без реальных изменений контента запрещено.

### 6.3. Общее правило
Любая страница, упавшая по трафику >30% за квартал или выпавшая из индекса, попадает в очередь refresh раньше планового срока. Приоритет refresh выше публикации новых страниц — поднимать существующее дешевле.

## 7. E-E-A-T: что добавить

1. **Страница `/about`** (новая, месяц 1): история школы, основатель (Дымова — имя в домене, это brand-актив), лицензии/документы если есть, филиалы с фото, цифры (лет работы, учеников, результаты ОГЭ/ЕГЭ). Schema: `LocalBusiness`/`EducationalOrganization`.
2. **`/about/prepodavateli` — страницы преподавателей:** карточка каждого: фото, образование, сертификаты (CELTA/TEFL/дипломы), стаж, специализация (возраст/экзамены), 2–3 предложения «о себе». При росте — отдельные страницы `/about/prepodavateli/<id>` с примерами занятий. Schema: `Person` через `employee`.
3. **Авторство статей:** каждая статья подписана реальным преподавателем (`Article.author` → `Person` с `url` на карточку). Статьи про экзамены и методику — двойная подпись: автор + рецензент (методист). Правило: AI-драфт допустим, но публикуется только после редактуры и подписи реального эксперта — имя автора отвечает за accuracy.
4. **Отзывы и кейсы (`/about/otzyvy`):** реальные отзывы с именем/фото по согласию, кейсы «было → стало» (баллы ЕГЭ, уровень) с цифрами. Schema: `Review`/`AggregateRating` только при реальных отзывах на странице.
5. **Проработка «о нас» в футере/контактах:** единый NAP (название, адреса филиалов, телефон) на всех страницах, совпадающий с Яндекс Бизнесом и картами — база локального E-E-A-T.
6. **Внешние подтверждения:** профили на картах/отзовиках, упоминания в локальных медиа Долгопрудного — включаем в план PR-активностей Phase 2+ (вне зоны этого документа, но фиксируем как зависимость).
