# Аудит архитектуры (Phase 0), 2026-08-28

## Текущее состояние

- **Сайт**: статический (prototype/ → dist_prod, Python-сборщики). ~90 страниц,
  SEO прокачано (см. SEO_*.md). Формы заявок → бот.
- **Бот/бэкенд**: FastAPI (~16k строк, bot/app), MAX + Telegram + веб-виджет,
  Mini App (2 штуки: MAX /app, TG /tg), админка /admin (RBAC), LLM-шлюз с
  ролями и PII-редакцией, SQLite CRM-store (клиенты/идентичности/сообщения,
  FTS5), watchdog, nudge, insights, дайджесты. 1007 тестов зелёные.
- **BigBen**: legacy lead-API (GET leads/add) — устаревший контур.

## Главные риски (до платформенного слоя)

1. Нет чтения CRM: бот/сайт не знают реальных групп, мест, расписания →
   риск галлюцинаций и записи «вникуда». ✅ закрыто платформенным слоем.
2. Legacy-интеграция без идемпотентности и вебхуков. ✅ закрыто.
3. SQLite как единая БД — предел масштабирования; приемлемо для текущей
   нагрузки, миграция на PostgreSQL — в roadmap.
4. Админка — CRUD-уровень; «операционная система школы» (Alert Center,
   Customer 360, автоматизации) — следующие фазы.
5. Нет платёжного контура (CloudPayments/T-bank) — фаза 8.

## Принятые решения

- Не строить параллельную Next.js-платформу: эволюция существующего стека
  (FastAPI + статический сайт) — быстрее до production-ценности, меньше риска
  сломать работающие каналы. Структура кода доменная (app/platform/*), при
  росте переносимо.
- BigBen v1 — единственный новый контур; legacy не трогаем до выключения.
